## Interpretation — why the gate fails, and why that is the honest reading

The **ruler** is a faithful, bit-exact port (see fidelity check below). The failure is in the
**round-trip**: the *canonical* centroid is a target the *generator* cannot reach at centroid params.
duke-lab names this the **medium residue** and ships its own instrument for it:
`effectiveCentroid` (L500-514) + `mediumResidue` (L559-570). Run on the pinned engine.js:

| artist | engine `median|effective - ideal|` | this receipt's median | agreement |
|--------|--------------------------------------|-----------------------|-----------|
| DUKE ELLINGTON | 0.2028 | 0.1857 | same order |
| BILL EVANS | 0.2115 | 0.2161 | match |
| THELONIOUS MONK | 0.3141 | 0.3419 | same order |

So the measured gap is a property of duke-lab's synthesizer + canonical centroids, **not** of the
port. The SPLINE protocol (DIALS.md §3) requires `distance(extracted, centroid') <= epsilon` before a
spline hop is trusted; this receipt shows that precondition is **not** met for roughly half the dials
when the generator is driven from the raw centroid. Per Library law, this is the
*"measurably fails — a failed dial is still a learned dial if journaled"* branch.

Structural notes:
- `harmonicComplex` is read from the **progression**, not the take (engine.js L388-390 stub + L423), so
  it is constant per artist and its error is fixed: duke 0.000, monk 0.021, evans 0.158.
- `trebleActivity` measures 0.000 for duke and evans (their centroids drive the treble-pressure rule to
  suppress the top shelf entirely); `restRatio` floors at 0.000 for duke (the density/rest params
  under-produce rests). These are generator floors, visible in `mediumResidue` too.

## JS semantics that resisted porting (all resolved)

1. **`%` sign.** JS `%` is a truncated remainder (sign of dividend): `-0.5 % 1 === -0.5`. Python's is
   floored (`0.5`). This flipped the swing branch on bar-line pickups (`onset = -0.5`, engine.js L242)
   and diverged 2 events/seed until fixed with `math.fmod`. **The single most dangerous porting trap.**
2. **`Math.round` half-up** vs Python banker's rounding → `jsround = floor(x+0.5)`.
3. **32-bit int arithmetic** in `fnv1a`/`mulberry32` (`|0`, `>>>`, `Math.imul`) → explicit
   `_i32/_u32/_imul` helpers. Required for a byte-exact RNG stream; without them every dial drifts.
4. **`charCodeAt` = UTF-16 code units** (astral chars split into surrogates) — handled in `fnv1a`.
5. **Dead-but-drawn RNG.** `nEvents` (L214) is computed and never used, yet consumes one `rng()`
   draw. Any 'cleanup' omitting it desynchronizes the whole downstream stream.
6. **`c[1] === null` never fires.** The `harmonicFromProg` guard tests root, but the seeded null
   chords carry root `0`; `w` always sums the c[2] weights, so `harmonicComplex` is take-independent.
7. **Stubbed dial.** `extractFeatures` returns 0.5 for `harmonicComplex` (L388); only `measureTake`
   fills it from the progression — hence `measure` without `--artist` leaves 0.5 (documented).
8. **Sort stability.** `Array.sort((a,b)=>a.t-b.t)` is stable; Python `sorted(key=...)` matches.
9. **`Math.floor(rng()*n)`** for cell/cellMem picks is floor, not `Math.round` — kept distinct.
