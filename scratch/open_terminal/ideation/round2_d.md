# skeptic-wedge — Round 2

## 1. What I concede

**C1. The OSC envelope from agent-network-grammar is better than my `@receipt` token.** I proposed `@receipt <hash>` as *the* agent-to-agent UX. That's wrong on two counts: it requires the agent to *type* something, and it makes the human's terminal visibly weird (a line of hash-looking text appears). The envelope (`\u001b]1338;v=1;verb;corr;budget;tier;room;hash\u0007` followed by the literal prompt text) is strictly superior because: (a) current terminals already *ignore* it, so the human sees the prompt text and nothing else; (b) it carries `corr`, `budget`, `tier`, and `room` in one transport, which is exactly the four things my receipt-only design kept trying to bolt on as separate tokens; (c) any agent that can `write()` participates — no SDK, no CLI, no `@`-token resolver in the pane runtime. I was building a client. He built a wire.

**C2. My "kill the plato UI" was overstated.** I said rooms are addressed, not rendered, and that full/gist/hint is a verbosity flag. agent-network-grammar's §2 shows the missing piece: **tier is a property of the pane's echo, not of the receipt.** The receipt ring always holds full fidelity; the *screen* is a rendering at the pane's declared tier. That's the honest mechanic — nothing is hidden, it's just not painted. My version implicitly assumed the receipt was the only artifact; his version makes the receipt the *substrate* and the tier the *projection*. I'll take his.

**C3. My "receiptd is the only product" was too narrow.** minority-human's receipt spot-check (§2) shows the human-facing surface I dismissed: hover the pane badge → right-click → *Audit Receipt* → a floating quilt-canvas panel that re-executes via champion_audit. I said "re-verification is a CLI they can run when they care." That's a developer's answer, not a supervisor's. The supervisor doesn't run CLIs; they right-click. I concede the human-facing verification surface is not optional — it's the thing that makes the fleet trust the terminal.

**C4. My tmux-control-mode step 2 was right but under-specified.** glm-5.3's process tree (`fleetd` broker + `receiptd`/`pinchd`/`conservd`/`quiltd` behind one unix socket, terminal as read-only subscriber) is the correct shape and I didn't draw it. My "terminal is just one client" claim needs the broker to be true; otherwise every plugin opens its own socket and we've rebuilt the monolith with extra steps.

## 2. What I steal, with mechanics

**S1. The OSC envelope as the one transport (from agent-network-grammar).**
I'm adopting the envelope verbatim and making it the *only* thing the terminal parses. Mechanic: the pane runtime is a 200-line parser that recognizes `ESC ] 1338 ; v=1 ; <fields> BEL`, strips it from the visible stream, and hands the following line to the agent session tagged with the envelope fields. Humans see the line. Agents see the line + fields. **Extension I'm adding:** the envelope's `hash` field is the *receipt head* the emitting agent claims to be at. The receiving pane's runtime compares it to its own view of `receiptd`'s chain for that corr. Mismatch → the receiving pane emits `verb=drift;corr=…;expected=<h>;got=<h>` back. This turns the envelope from a transport into a *continuously verified* transport — every ask/answer pair is a free consistency check on the receipt chain. That's the part agent-network-grammar left on the table and it's the part that makes receipts load-bearing instead of decorative.

**S2. The right-click Audit Receipt surface (from minority-human).**
Mechanic: the pane badge (his §1) is a *receipt head indicator* — a single glyph whose color is the three-valued verdict of the last receipt in that pane's chain (green ✓ = re-executed and matched, amber ? = never re-executed, red ✗ = re-executed and diverged). Hovering shows the last claim in a tooltip. Right-click → *Audit Receipt* spawns a quilt-canvas panel via `quiltd`'s socket that pulls the last N receipts and offers a `champion_audit` button. **Extension I'm adding:** the audit panel is itself a pane in a hidden `room=_audit`, so the audit *produces a receipt* (the audit receipt cites the audited receipt's hash). This closes the loop — you can audit the audits, and the fleet's trust graph is a DAG, not a tree. minority-human's version was a one-shot check; mine is a chain.

**S3. glm-5.3's process tree, adopted wholesale.**
`tmux server` (lanes) → `fleetd` (broker, `/run/si/fleet.sock`, JSON-lines, pub/sub with a filter grammar) → `receiptd` / `pinchd` / `conservd` / `quiltd` behind it → terminal as read-only subscriber. The load-bearing property I'm stealing: **terminal dies, nothing agent-side dies.** Every design decision below assumes the terminal is a view. The one thing I'm adding to his tree: `receiptd` owns the *only* append-only file; `fleetd` is stateless fan-out; `pinchd` holds the 5,138-card index in RAM and serves on a *separate* socket (`/run/si/pinch.sock`) because it's on the keystroke path and a broker hop costs latency we can't spend.

## 3. Revised top-5, ranked

### #1 — `receiptd` + the OSC envelope with receipt-head verification
**Mechanic.** `receiptd` is a unix-socket daemon owning one append-only JSONL chain per lane, plus an mmap hash index. Every agent turn writes one receipt: `{h_prev, h, lane, corr, input_hash, output_hash, tier, room, budget:{tok,wh,usd}, verdict ∈ {-1,0,+1}}`. The OSC envelope (§S1) carries the emitting agent's claimed `hash`; the receiving pane verifies against its view and emits `verb=drift` on mismatch. Trust = re-execution: `receiptd verify <corr>` shells into champion_audit, compares outputs, writes a *new* receipt whose claim is "receipt X re-executes to Y." Human surface: the pane badge (three-valued color) + right-click audit panel (§S2).
**Why it survives the skeptics.** (a) MS will not build this — it requires a fleet with a re-execution sandbox and a culture where trust = re-run. (b) It's out-of-process by construction; the box can crash the terminal and the chain is intact. (c) It subsumes activelog (front = claim, back = hash+io), conservation (budget field), the three-valued gate (verdict enum), and the pinch target (pinch matches claims against prior receipts). (d) The envelope makes it *invisible* to humans — they see a terminal tick, not a ledger. My round-1 version required typing `@receipt`; this version requires nothing from the human and nothing from the agent beyond `write()`.
**First buildable slice.** `receiptd` with `append`/`get`/`verify` over a unix socket, JSONL store, SHA-256 chain, and a 20-line CLI (`receipt append …`, `receipt verify <corr>`). No terminal integration yet. Test: two shell scripts produce receipts, a third verifies the chain, a tampered line fails verification. Ship this before touching the terminal.

### #2 — `fleetd` broker + tmux-control-mode lanes (the fleet console)
**Mechanic.** `fleetd` is a stateless pub/sub broker on `/run/si/fleet.sock`: JSON-lines, `{v:1, id, ts, lane, type, payload}`, subscribe with a filter grammar (`type:receipt,lane.*`). It owns the tmux control-mode (`tmux -CC`) connection to each host (local + SSH per DDKinger), translating control-mode `%output`/`%window-add`/`%session-changed` events into lane lifecycle events. Every pane in the terminal is a *view* onto a lane; the lane persists in tmux when the terminal dies (leverage upstream's keep-running/post-reattach). Remote agents are first-class: SSH + control mode = structured events, not PTY scrape. tmux hooks give live agent status on the remote without ACP there.
**Why it survives the skeptics.** (a) This is the only fork divergence in the entire ecosystem pushing on remote sessions (DDKinger, 4 commits, by an upstream WT contributor). (b) It's the wedge MS won't build because it requires *a fleet spanning machines with a shared ritual*, not a Windows feature. (c) Terminal-as-subscriber means the box crashing under GPU load doesn't kill agent lanes — the single most important resilience property given the crash constraint. (d) It's the substrate every other feature rides: receipts are per-lane, pinch routes to lanes, conservation meters per-lane, quilt panels are lanes.
**First buildable slice.** `fleetd` connects to one local tmux server via `tmux -CC`, subscribes to `%output` and `%window-add`, and emits lane events to `socat - UNIX-CONNECT:/run/si/fleet.sock`. No terminal integration. Test: `tmux new-window`
